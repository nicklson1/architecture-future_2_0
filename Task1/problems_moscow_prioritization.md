
## 🗂️ Приоритизация проблем по методу MoSCoW

| Приоритет  | Проблема                                                                 |
|------------|--------------------------------------------------------------------------|
| **Must**   | **Централизация логики в DWH** — тормозит развитие и масштабирование.   |
| **Must**   | **Старое оборудование и ПО** — увеличивает риски и затраты.             |
| **Must**   | **Медленная генерация отчётов** — напрямую влияет на бизнес-решения.    |
| **Should** | **Нет гибкой системы доступа к данным** — возможны нарушения регуляций. |
| **Should** | **Сложные и неунифицированные интеграции** — мешают подключать новые компании. |
| **Could**  | **Нет стандартизированных API и витрин** — мешает автоматизации, но не критично. |
| **Could**  | **Нет разделения по направлениям бизнеса** — создаёт неэффективность, но можно жить. |
| **Won’t**  | **BI зависит напрямую от DWH** — решится автоматически при рефакторинге. |
